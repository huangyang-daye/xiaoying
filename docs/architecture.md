# 项目范围与架构约束

## 产品目标

实现一个可独立部署、独立运行的素材制作网站，覆盖模板浏览、图片上传、制作任务提交、后台处理、个人历史记录和制作结果查看。

当前阶段只记录方向，不创建页面、业务接口、数据库表或任务执行器。

## 系统职责

### Next.js 前端

- 使用 App Router、React 和 TypeScript。
- 承担页面展示、用户交互、任务状态与结果展示。
- 可以直接请求 Java API，也可以通过 Next.js 接口中间层转发请求。
- 不独立承担核心业务执行与持久化。

### Java 后端

- 使用 Java、Spring Boot 和 MyBatis。
- 提供模板、素材、制作任务和个人记录相关业务接口。
- 负责业务校验、任务接收、后台执行协调及数据读写。
- 任务提交与实际制作过程解耦，避免用户必须停留在提交页面等待制作完成。
- 用户离开页面或刷新后，仍可通过持久化数据查询任务和历史记录。

### MySQL

- 作为任务状态、历史记录和相关业务数据的持久化来源。
- 前端内存、浏览器缓存或 Next.js 进程内存不能作为任务与历史记录的唯一来源。
- 图片和制作结果文件的存储方式待确定；文件与数据库记录的关联由后端管理。

## 概念调用链

```text
浏览器 → Next.js 页面 → Java 业务 API → MyBatis → MySQL
                    ↘ 可选 Next.js 中间层 ↗

Java 接收制作任务 → 后台处理 → 更新 MySQL 中的状态与记录
浏览器查询任务与历史记录 → Java 业务 API → 返回状态与结果信息
```

后台任务的具体执行机制和部署拓扑在后续设计阶段确定。此处不预设消息队列、独立 Worker 或具体制作引擎。

## 后续设计事项

- 模板的数据结构、管理方式和制作规则。
- 图片上传限制、文件存储与结果访问方式。
- 用户身份、个人记录归属和访问权限。
- 任务状态流转、失败处理、重试及并发控制。
- 状态更新方式，例如轮询或服务端推送。
- 前后端依赖版本、数据库结构和 API 契约。
- 本地开发、独立部署和配置管理方式。

以上是后续需要设计的事项，不代表当前已实现或已选定具体方案。
