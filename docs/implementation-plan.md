# 素材制作网站实现方案（规划稿）

## 1. 依据与当前边界

本方案依据仓库根目录的《任务要求.md》及已确认技术约束编写。源文档中的要求用于定义后续交付目标；本次用户请求仅授权任务规划，不代表现在执行文档中的开发、安装、部署或测试命令。

当前没有实现应用、接口、表结构、执行器、测试或容器配置。本文的“采用”“提供”等描述均指计划实现。除题目硬性要求外，具体设计和默认值均为方案建议，尚未作为用户确认的最终决定。

参数名称、可选值、范围和默认值集中见 [参数字典](parameter-catalog.md)。源文档保持原样，不以本方案覆盖。

## 2. 具体交付目标与范围

完成“选择模板 → 上传服务端素材 → 提交后立即获得任务 ID → Java 后台分阶段执行 → 浏览其他页面或继续提交 → 查看个人结果 → 刷新恢复”的完整闭环。

- 制作使用确定性的模拟生成器，不调用真实 AI；输出是可访问的示例图片。
- 至少准备 3 个分类、6 个模板，覆盖需要 1、2、3 张图片的情况；这些数量是建议演示基线，并非题目硬性数量要求。
- 必须完成三阶段：素材检查、模拟生成、结果整理；每阶段都有服务端记录和独立执行边界。
- 演示身份 A、B 各自拥有素材、任务与历史，能够验证隔离。
- 完成前端、Java 后端、MySQL 初始化、核心测试、CI 和交付说明；推荐包含 Compose。
- 不增加支付、会员、积分、模板管理后台、真实 AI、视频、第三方登录、自动重试、重新制作、任务取消和集群运维。

## 4. 建议架构与关键取舍

### 4.1 请求和文件路径

采用单仓库 `frontend/`、`backend/`、`database/`、`docs/`。浏览器访问 Next.js；同源 `/api/*` 和 `/files/*` 经 Next.js 代理转发到 Java。代理只转发请求、响应和 Cookie，Java 执行业务与权限校验。Java 与 MySQL 在内部网络连接。

上传文件和结果放在后端数据卷，用数据库保存相对存储键；不把浏览器 blob URL、宿主机绝对路径或任意客户端文件路径作为结果地址。公开示例封面可公开访问；个人素材和结果通过 Java 校验会话归属后读取。临时预览 URL 在替换、移除和卸载时释放。

框架具体版本在工程建立前验证兼容性并固定到 README、构建文件和锁文件。本次不根据未经验证的版本号承诺兼容性，也不安装依赖。

### 4.2 异步执行

建议使用“MySQL 等待队列 + Java 单工作线程”，不引入 Redis 或消息队列。后台定期寻找最早的 QUEUED 任务，通过带状态条件的更新认领，确保一次只认领一个任务；同一时刻执行一个制作任务，其余排队。HTTP 请求线程不承担制作过程。

创建任务的事务包含任务记录、素材关联、三条待执行步骤、模板及模拟配置快照；事务提交后任务才可被后台发现。步骤的开始、成功、失败均单独提交短事务；模拟等待期间不持有数据库事务或行锁。GET 查询只读数据库，不推进任务。

第一步执行前保存 RUNNING 和开始时间。非末步骤执行成功后，在同一短事务中保存该步 SUCCEEDED/结束时间、下一步 RUNNING/开始时间及任务新阶段，再实际调用下一步，避免暴露整体阶段与步骤状态不一致的中间快照。任一步异常：该步 FAILED，后续步骤 SKIPPED，任务 FAILED，保存失败阶段和可读原因。最后一步仅在结果文件写入完成、确认可访问后，再在同一事务中提交末步成功、结果元信息和任务 SUCCEEDED。

队列调度器和制作工作线程与 HTTP 线程独立；配置有界执行容量，队列来源是 MySQL，不能只依赖内存 Future 保存任务。

### 4.3 重启边界

浏览器关闭不会影响 Java 执行。服务重启后 QUEUED 任务可继续被扫描；原 RUNNING 任务建议在启动时标记 FAILED，错误码 RESTART_INTERRUPTED，未完成步骤按失败/跳过归档，不自动续跑。已成功、已失败任务保持终态。这是单后端实例方案，不支持多实例同时启动的恢复判断；后续若扩展多实例需另行设计租约。

自动恢复正在执行的任务不在题目要求内，上述处理是可解释的建议策略，需要在 README 明确。文件写入后数据库提交失败可能留下孤立文件，作为已知限制记录，不将其显示为成功结果。

### 4.4 模拟生成器

三个独立步骤组件依次调用。每个步骤先等待其配置耗时，再检查是否指定在该步骤失败；成功时继续下一步。模拟生成选择模板绑定的本地预置图片，结果整理复制到该任务独有结果路径并登记元信息，不要求真正合成上传图片。

本地演示配置开启模拟参数入口：详情页可折叠的“演示控制”区域提交 `simulation`。关闭该入口时服务端拒绝客户端传入模拟控制参数，使用服务端默认配置；不能仅隐藏前端控件。

## 5. 状态机与一致性

整体状态：`QUEUED → RUNNING → SUCCEEDED | FAILED`。QUEUED 也可因后台调度故障进入 FAILED；终态不能回到非终态。任务不存在“查询失败”业务状态。

当前阶段：`NOT_STARTED → MATERIAL_CHECK → MOCK_GENERATION → RESULT_ASSEMBLY → COMPLETED`。阶段失败时停留在失败阶段，`failureStage` 指向它；调度前失败时 failureStage 为空。任务成功时当前阶段为 COMPLETED。

步骤状态：`PENDING → RUNNING → SUCCEEDED | FAILED`；未执行的后续步骤可由 PENDING 变为 SKIPPED。每个任务固定三条步骤记录；任务当前阶段与步骤记录在同一状态更新事务内保持一致。

关键不变量：成功任务必须有 resultId/resultUrl；失败任务必须有 errorCode/errorMessage；阶段失败必须有 failureStage；结果只在结果整理成功后对外可见。按状态条件更新防止终态倒退；新模板配置不得改变旧任务的素材要求快照。

## 6. 前端页面与异步管理

| 路由建议 | 主要区域与行为 |
| --- | --- |
| `/templates` | 顶部导航/演示身份、分类栏、封面卡片网格、加载/空列表/失败重试 |
| `/templates/[id]` | 模板标题说明和示例、素材约束、上传槽位、提交按钮、演示控制、任务受理反馈 |
| `/history` | 当前身份的任务列表、时间/状态/阶段、分页、结果缩略图或失败原因、未完成任务状态更新 |
| `/tasks/[id]` | 任务三阶段详情、队列/处理状态、结果预览、查询错误及恢复查询按钮 |

参考已存在的列表截图，采用分类导航和大图卡片网格，主要布局保留，品牌/视频/积分/会员/国际化不纳入范围。源文档另外三张远程截图本次读取失败，详情与历史布局目前按正文提出建议；实现前需核对可读取的参考图，不声称已完成截图对应验证。

前端建议使用 React reducer + 原生 fetch/AbortController，避免为状态管理强制引入额外服务或库：

- 素材以 slotIndex 管理；替换时递增上传版本，旧请求晚到也不能覆盖新图片。
- 提交状态只表示 POST 的生命周期；收到任务 ID 后恢复 IDLE，把任务交给独立跟踪器。
- 任务缓存键为“身份 + taskId”；业务状态和 queryStatus 分开，不用查询异常覆盖 task.status。
- 轮询器位于身份会话布局中，浏览模板、详情和历史时仍可跟踪；页面展示订阅同一份任务数据。
- 刷新/进入会话布局时拉取历史和全部活动任务；活动任务接口分页时读取全部页，不能只跟踪历史第一页。
- 每个任务在上次请求结束后再安排下次查询，避免重叠请求。成功/失败即停止；没有活动任务时无轮询请求。
- 查询失败保留已有信息，暂停该任务自动查询，提供手动恢复；浏览器离线可提示网络异常，不改变任务状态。
- 身份切换或离开会话布局时取消定时器和请求，并递增会话版本；即便取消后旧请求返回，也不能写入新身份数据。上传和提交响应同样检查会话版本。
- 查询请求与本地提交返回通过 taskId 合并；读取结果以服务端更新时间/版本为准，避免迟到的旧响应覆盖终态。

## 7. 数据模型与接口契约草案

只规划实体和边界，本步不生成 SQL 或接口实现。

| 实体 | 主要字段与约束 |
| --- | --- |
| demo_user | id、demoKey、displayName；两条种子身份 |
| template_category | id、name、sortOrder |
| template | id、categoryId、title、description、coverKey、requiredImageCount、acceptedMimeTypes、maxFileSizeBytes、sampleResultKey |
| asset | id、ownerId、originalName、storageKey、mimeType、sizeBytes、createdAt；仅上传完整且验证通过后入库 |
| production_task | id、ownerId、templateId、templateSnapshot、status、currentStage、failureStage、errorCode、errorMessage、simulationSnapshot、resultId、version、createdAt、startedAt、finishedAt、updatedAt |
| task_asset | taskId、assetId、slotIndex；同一任务槽位唯一，素材顺序可恢复 |
| task_step | taskId、stage、sequence、status、startedAt、finishedAt、errorCode、errorMessage；taskId+stage 唯一 |
| task_result | id、taskId、ownerId、storageKey、mimeType、sizeBytes、createdAt；每任务一个图片结果 |

历史以 production_task 为数据源，不额外复制一套容易不同步的历史表。索引覆盖 ownerId+createdAt+id、status+createdAt+id、taskId；时间以 UTC 存储并通过 ISO 8601 返回，浏览器按本地时区展示。ID 统一用不透明字符串，BIGINT 如选用也不得以可能丢精度的 JSON number 暴露。

| 方法与路径建议 | 请求核心字段 | 响应与约束 |
| --- | --- | --- |
| POST `/api/session/demo` | demoKey | 设置演示会话 Cookie，返回 user；仅演示模式可用 |
| GET `/api/session` | 无 | 当前 user；无有效会话为 401 |
| GET `/api/categories` | 无 | 分类数组 |
| GET `/api/templates` | categoryId、page、pageSize | items、total、page、pageSize |
| GET `/api/templates/{id}` | 路径 id | 模板详情及素材要求；不存在返回 404 |

| POST `/api/tasks` | templateId、按槽位顺序的 assetIds、可选 simulation | 202；返回持久化后的 taskId、QUEUED 及查询地址；不等待执行完毕 |
| GET `/api/tasks` | status（可重复）、page、pageSize | 当前用户历史；createdAt DESC、id DESC 稳定排序 |

所有 ownerId 从 Java 会话派生，不接受客户端通过 userId 指定记录归属。JSON 错误响应统一 errorCode、message、fieldErrors（可选）、traceId；所有个人列表按会话过滤，他人资源与不存在资源统一返回 404。成功受理后若客户端断网，任务仍可能创建，前端先刷新个人记录再提示用户决定是否重提；本期不承诺提交接口幂等。

## 9. 核心测试与演示矩阵

| 场景 | 预期验证点 |
| --- | --- |
| 全步骤成功 | 顺序严格为检查→生成→整理，三条步骤均成功且有时间，结果地址可打开 |
| 检查失败 | 第一条失败，其余 SKIPPED；无成功结果；失败阶段与原因持久化 |
| 生成失败 | 检查成功、生成失败、整理 SKIPPED |
| 整理失败 | 前两步成功、整理失败，无可见成功结果 |
| 多任务排队 | 连续提交三个任务，ID 独立，状态/图片/错误互不覆盖 |
| 查询请求异常 | 模拟 GET 网络失败，任务保留原状态；恢复查询后能看到实际终态 |
| 刷新/关闭页面 | Java 继续处理；重开后从后端恢复历史及活动任务 |
| 身份切换与迟到响应 | A 的请求晚到不污染 B；B 无法直接读取 A 的素材和结果 |
| 上传替换竞争 | 旧上传晚完成不覆盖新槽位；错误类型/超限/数量错误被服务端拒绝 |
| 查询与终态 | 反复 GET 不驱动执行；无活动任务时无自动轮询；终态不会倒退 |
| 后端重启 | 成功历史仍在；原 RUNNING 按声明标记中断失败，原 QUEUED 可调度 |
| 容器交付 | 干净数据卷能初始化；已有数据卷不被重复种子覆盖；文件和 DB 均持久化 |

后端单元测试通过可替换的等待器和步骤桩控制行为，避免真实长时间 sleep；关键事务、MyBatis 查询和归属检查在 MySQL 容器中集成验证。前端用可控请求桩和模拟时钟验证并发与清理。无需为满足数量堆积测试，也不要求浏览器端到端测试。
