# 多任务异步与事务一致性

验收实现：`730d70d3ff55b1c2601a8b51162b3e00c1c69371`。改造日期：2026-11-02。范围是单 Java 实例内多个任务并行，保留任务内部三阶段顺序；不包含集群执行、自动续跑或提交幂等。

## 调度与事务边界

- 数据库中的 QUEUED 记录是持久化待执行队列。受理事务原子创建任务、素材关联、三个 PENDING 步骤，提交后 HTTP 返回 202。无需依赖进程内通知或提交后立即启动线程。
- 调度线程只提交执行机会，不执行耗时制作。固定大小线程池配合 Semaphore、SynchronousQueue 和拒绝策略，默认同时执行 4 个任务，配置范围 1～32。线程池满或关闭时不会预先认领任务，任务仍留在数据库。
- 工作线程在独立 READ_COMMITTED 事务中用 SELECT … FOR UPDATE SKIP LOCKED 取得候选任务，再条件更新 QUEUED→RUNNING，同时启动首步骤。没有可用行时允许本轮返回空，由后续调度继续扫描。
- 每次阶段迁移先锁定任务父行，再校验当前状态、阶段和步骤。结束当前步骤与启动下一步骤在同一短事务提交；任务 UPDATE 同时检查 version 并递增，检查所有写入影响行数。
- 模拟耗时和图片内容准备在事务外执行，避免长事务占据连接和行锁。一个阶段失败后，在独立事务中同时保存整体失败、失败步骤及后续 SKIPPED，不撤销之前已成功阶段。
- 成功和失败竞争同一任务时，通过父行锁串行化；终态不被后续失败或过期阶段更新覆盖。历史与任务详情使用 REPEATABLE_READ，读到同一提交快照中的任务与步骤。

## ACID 对应关系

| 属性 | 实现 |
| --- | --- |
| 原子性 A | Spring 事务覆盖每个业务状态迁移；任一校验或 SQL 写入失败均回滚本次任务、步骤和结果写入。完整制作由多个独立短事务组成，而非一个覆盖全部等待时间的长事务。 |
| 一致性 C | 阶段状态机、步骤检查、任务版本条件更新、素材关联外键及结果主键/级联外键共同维护约束；失败后续步骤跳过。 |
| 隔离性 I | 认领使用 SKIP LOCKED；更新先锁任务行；受理与账户删除先锁账户行；查询使用一致性快照。 |
| 持久性 D | 使用 MySQL 8.4 默认 InnoDB 的事务日志与提交持久化机制，数据保存于 Compose mysql_data 卷。部署需保留持久化卷及可靠磁盘，保持 innodb_flush_log_at_trx_commit=1 等提交持久化配置。 |

## 结果与文件

V6 新增 task_result(task_id, content)。新本地模拟结果不再写独立 results 文件：图片字节、result_size、最终步骤完成及 SUCCEEDED 状态在同一数据库事务中提交。最终提交前失败或崩溃时，这几项一并回滚；提交后结果 URL 可直接从数据库读取字节。

GET /files/results/{id} 路径及会话权限不变。V6 之前的文件结果继续通过 result_key 读取，不强制搬迁历史文件。已有模板的外链结果仍保存 URL 快照，数据库只能原子保存其元信息，不能保证外部站点内容可用。

上传素材和旧结果仍使用文件系统，不能宣称与 MySQL 具有分布式 ACID。素材上传先保存文件再写记录；遗留文件需要后续清理。账户删除在数据库事务中锁定账户及所属任务，级联删除新结果；文件清理延迟至 afterCommit。删除回滚时不提前删除文件，提交后清理异常则可能留下孤立文件。

## 并发完成时的刷新恢复

活动列表在分页间会因任务结束而缩短，直接使用 OFFSET 可能漏掉仍在运行的任务。GET /api/tasks/active 新增 before，响应增加 nextCursor，按 created_at DESC / id DESC 进行稳定游标扫描。游标记录即使已经完成，仍能作为下一页边界。前端恢复优先使用游标，直到 nextCursor 为空；继续兼容没有游标字段的旧测试传输。

新版本服务仍接受原 page/pageSize 查询。普通模板列表及历史列表保留现有分页方式；活跃任务恢复使用 before，以避免状态变更造成的偏移。

## 运行与迁移

1. 备份数据库及 backend_files 卷；保留现有 Flyway V1～V5 不变。
2. 在 .env 配置 TASK_WORKER_CONCURRENCY（默认 4），执行 docker compose up -d --build --wait。Java 自动执行 V6，旧结果继续可读。
3. 在界面的演示控制中延长生成阶段，连续提交超过并发上限的任务。可观察多个 RUNNING 和剩余 QUEUED；同一任务阶段仍顺序执行。
4. 并发设为 1 可恢复串行执行策略，无需迁移数据。回滚旧镜像前应注意旧代码不能读取 V6 新结果字节；已有新结果时应保留兼容代码或从配套备份恢复，不能直接假定新旧结果格式兼容。

工作池关闭时先等待 10 秒，之后中断仍在执行的工作线程，并尝试记录中断失败。强制退出或数据库不可用可能留下 RUNNING；重启归档仍按原规则将其置为 RESTART_INTERRUPTED，QUEUED 继续执行。当前恢复逻辑以单实例为前提，不能直接扩容多个 Java 实例，否则启动归档可能干扰另一实例的任务。
